# 切面底座决策

架构分工以已经打开的 2022 年文章为准。T/TAF 162—2023 的 PDF 没有打开，它的正文条款不进入本决定。

## 打开了什么

中兴通讯技术 2022 年 12 月（第 28 卷第 6 期，DOI `10.12142/ZTETJ.202206011`）韦韬、顾为群、刘宇江《安全平行切面：面向企业数字生命体的安全基础设施》已整篇抽出。下面的底座 / 应用划分来自这篇文章。

T/TAF 162—2023《移动应用安全平行切面技术指南》的发布地址没有返回文件：`taf.org.cn:443` 在 TLS 握手后对端直接关闭（读到 0 字节），`http://` 同一主机则是空回复。公开著录页 `https://www.biaozhuns.com/archives/20230601/show-343131-108-1.html` 打开了，只确认这些书目事实：电信终端产业协会，2023-04-26 发布并实施，英文名 Technical guidelines for aspect-oriented security of mobile applications，起草单位包括蚂蚁科技集团股份有限公司，范围是移动应用安全平行切面的架构和部署指南。著录页没有底座功能条款。检索摘要里出现过的「配置读取、切点植入、数据上报、模块加载」没有随 PDF 打开，本决定不把它们写成该标准的条款。

《安全平行切面总体技术要求》的全文没有取到。刘宇江 2025-11-11 的访谈页（`https://www.iedumedia.com/news/newsinfo/545`）写明该文件已通过团体标准评审、还在发布流程中。不作为实现规格，也不补写条款。

JVM-Sandbox 的事件模型和 SOFAArk 的类隔离不是这篇 2022 文章定义的切面标准，本仓库不把它们当成这套标准来实现。

## 文章里的分工

业务空间旁边是一块平行空间。不改源码、靠注入或代理加进去的逻辑叫切面应用，作用在一个或一组切点上，对原来的执行做观测或干预。切面应用由切面核心的加载器装进各自的切面平行舱。平行舱有三点：隔离、可调度、可管控。依赖留在自己的命名空间里，不污染业务空间；核心按优先级调度各应用；应用出错时由核心挡住，核心自己出错时由统一代理兜底，业务调用照旧返回。大规模部署再分成切面安装器、切面核心、切面应用。云端管控端按语言和版本决定装哪一包。RASP、IAST 和数据血缘在文章里是切面应用，不是核心。

## 决定

weaver-girl 站在切面核心这一侧：负责切点植入、模块加载、观测出口，以及在一个类变换失败时让 JVM 和兄弟类继续跑。它不是切面应用，也不是云端管控端。

这个仓库已经有的：

- 切点植入：`WeaverTransformer` 按已注册切点改类。一个类在变换里抛出（含 `Error`）时不安装新字节，原方法仍可调用，同一次安装里的其他类继续增强，进程不退出。失败记在 `AgentDiagnostics`，由现有的 `GET /diagnostics/faults` 列出。这是文章里「核心或代理出错时不把业务带倒」的窄实现。
- 模块加载：拦截器注册表、插件模块，以及 `AnnotationPluginLoader`。对应文章里核心的加载器，不是按应用划分的平行舱命名空间。
- 观测出口：`JsonEventListener`、Prometheus 导出，以及 `AgentApiServer` 上的 `GET /events`、`GET /diagnostics/faults`、`GET /jvm`。对象是本进程的操作员。
- 本机配置：YAML（见 `docs/yaml-config-reference.md`）。读的是随进程提供的文件，不是云端管控端下发的部署策略。

平行舱的隔离、可调度、可管控，这里只落到「一个类变换失败不拖垮 JVM 和兄弟类」。没有按切面应用划分的命名空间，没有按优先级调度多个切面应用，也没有按许可收紧应用能做的动作。

明确不做上层：云端控制面、阻断或 NbSP 白名单、RASP 或可信模块，以及移动端、内核、服务网格上的切点。这些留在切面应用和云端管控端。

本决定不改变生产字节码，编译目标仍是 Java 8。
