# 切面底座决策

采用公开切面标准里的底座 / 应用分工。weaver-girl 只做底座。

## 打开了什么

T/TAF 162—2023《移动应用安全平行切面技术指南》（电信终端产业协会，2023-04-26 发布并实施）把移动端切面组件分成切面底座和切面管控。底座与管控分开。底座负责四项：配置读取、切点植入、数据上报、模块加载。管控放各场景的切点处理，再经底座把观测送出去。四项的含义是：配置读取取云端切面管控平台发下来的切面配置；切点植入在预编译或运行时用动态代理把切点放进目标；数据上报把管控模块看到的数据经底座送到云端平台；模块加载由底座装入切面管控里对应的模块。起草单位包括蚂蚁科技集团股份有限公司，见公开著录页 `https://www.biaozhuns.com/archives/20230601/show-343131-108-1.html`。同一官方 PDF 的直连没有拿到字节：`taf.org.cn:443` 在 TLS 握手后对端关闭，读到 0 字节。上面四项来自该 PDF 已被索引返回的正文，不是著录页。

中兴通讯技术 2022 年 12 月（第 28 卷第 6 期，DOI `10.12142/ZTETJ.202206011`）韦韬、顾为群、刘宇江《安全平行切面：面向企业数字生命体的安全基础设施》已整篇抽出。切面应用放在切面平行舱里。平行舱有三点：隔离、可调度、可管控，使一个应用拖不垮宿主进程。文章里的部署件是切面安装器、切面核心、切面应用。RASP、IAST 和数据血缘写在切面应用一侧。

《安全平行切面总体技术要求》的全文没有取到。刘宇江 2025-11-11 的访谈页（`https://www.iedumedia.com/news/newsinfo/545`）写明该文件已通过团体标准评审、还在发布流程中。不作为实现规格，也不补写条款。

JVM-Sandbox 的事件模型和 SOFAArk 的类隔离不是这两份材料定义的切面标准，本仓库不把它们当成这套标准来实现。

## 分工

标准：底座做配置读取、切点植入、数据上报、模块加载。切面管控做场景处理，与底座分开。

2022 年文章：不改源码、靠注入或代理加进去的逻辑是切面应用，作用在一个或一组切点上。切面应用由切面核心的加载器装进各自的平行舱。依赖留在自己的命名空间里；核心按优先级调度；应用出错时由核心挡住，核心自己出错时由统一代理兜底。云端管控端按语言和版本决定装哪一包。

## 决定

weaver-girl 就是切面底座，不是切面应用，也不是切面管控。

这个仓库已经有的：

- 配置读取：本机 YAML（见 `docs/yaml-config-reference.md`）。读的是随进程提供的文件，不是云端切面管控平台下发的配置。
- 切点植入：`WeaverTransformer` 按已注册切点改类。一个类在变换里抛出（含 `Error`）时不安装新字节，原方法仍可调用，同一次安装里的其他类继续增强，进程不退出。失败记在 `AgentDiagnostics`，由现有的 `GET /diagnostics/faults` 列出。
- 数据上报：`JsonEventListener`、Prometheus 导出，以及 `AgentApiServer` 上的 `GET /events`、`GET /diagnostics/faults`、`GET /jvm`。对象是本进程的操作员，不是云端管控平台。
- 模块加载：拦截器注册表、插件模块，以及 `AnnotationPluginLoader`。装的是本仓库的拦截器与插件，不是标准里的切面管控模块，也不是按应用划分的平行舱。

平行舱的隔离、可调度、可管控，这里只落到「一个类变换失败不拖垮 JVM 和兄弟类」。没有按切面应用划分的命名空间，没有按优先级调度多个切面应用，也没有按许可收紧应用能做的动作。

## 上层不做

明确延后，不进这个代理：云端控制面、阻断或 NbSP 白名单、RASP 或可信模块，以及移动端、内核、服务网格上的切点。这些留在切面应用和切面管控。

## 编译目标

本决定不改变生产字节码，编译目标仍是 Java 8。
